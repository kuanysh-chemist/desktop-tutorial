# Генератор КСП по химии · Химиядан ҚМЖ генераторы

Веб-приложение для учителей химии Казахстана: собирает краткосрочный план
урока (КСП) по форме приказа Министра образования и науки РК от 6 апреля
2020 года № 130 и выгружает его в **.DOCX** и **.PDF** на русском и казахском
языках.

Учитель заполняет вручную три поля — **тему урока**, **цели обучения** и
**время урока**. Этапы урока, действия педагога и обучающихся, оценивание,
ресурсы, дифференциация и техника безопасности генерируются автоматически и
остаются полностью редактируемыми.

## Как это выглядит и работает

Слева — три поля, которые заполняет учитель, и сразу под ними кнопка сборки:
до главного действия не нужно прокручивать страницу. **Ctrl + Enter** собирает
план прямо из поля ввода. Под кнопками видно, что именно подставила система:
найдена ли тема в базе, какой опыт выбран, какие активные методы и цифровые
ресурсы попали в урок и какой это по счёту сценарий.

Методические блоки и библиотека планов вынесены в отдельные карточки ниже.
Панель «Скачать DOCX / PDF / Печать / Сохранить» закреплена сверху и остаётся
на месте, пока учитель прокручивает длинный план. На телефоне колонки
складываются в одну, а после сборки страница сама прокручивается к документу.

## Быстрый старт

```bash
npm install
npm run dev     # http://localhost:3000
```

Сборка и запуск в продакшене:

```bash
npm run build && npm run start
```

## Автономная версия: один файл, без интернета

Кроме обычного сайта проект собирается во **второй форме — один HTML-файл**,
который открывается двойным щелчком. Ни интернета, ни установки, ни хостинга,
ни учётной записи: всё приложение, включая базу знаний, шрифт и сборщики DOCX
и PDF, лежит внутри файла.

```bash
npm install
npm run build:standalone     # dist/ksp-generator.html, около 3,7 МБ
```

Файл можно положить на флешку, отправить коллеге или оставить на рабочем столе
школьного компьютера. Проверено: работает с `file://`, переживает перенос в
другую папку, не делает ни одного сетевого запроса, сохраняет библиотеку планов
в браузере и скачивает DOCX и PDF с правильными именами.

Единственное отличие от сайта — нет кнопки «Доработать через Claude»: обращаться
к API неоткуда, поэтому кнопка не показывается вовсе, а не выдаёт ошибку.

Обе сборки используют один и тот же код: страница Next.js и автономная точка
входа рендерят общий `components/KspApp.tsx`.

## Стек

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 ·
`docx` для Word · `pdfmake` для PDF · `@anthropic-ai/sdk` (необязательно).

## Как устроена генерация

Движок **гибридный**, и локальная часть в нём основная:

| Слой | Файл | Роль |
|---|---|---|
| Разделы программы | `lib/kb/curriculum.ts` | 27 разделов за 7–11 классы с двуязычными названиями и перечнем подтем. Поле «Раздел долгосрочного плана» в шапке КСП берётся отсюда |
| База знаний | `lib/kb/grade7.ts` … `grade11.ts` | 107 тем: опыты с реактивами, техникой безопасности и виртуальной альтернативой, термины RU/KZ/EN для CLIL, критерии оценивания и дескрипторы |
| Сборка и поиск | `lib/chemistry-kb.ts` | Объединение тем, сопоставление темы урока с базой, универсальный каркас для тем вне покрытия |
| Педагогика | `lib/pedagogy.ts` | 7 ведущих методик с описанием и примером по химии (проблемное обучение, исследовательское/STEM, ТРКМ, CLIL, групповая работа, кейс, перевёрнутый класс), 20 приёмов формативного оценивания, 5 стратегий дифференциации и по три пары «поддержка / усложнение» на каждый характер темы, 10 форматов домашнего задания, ценности, базовая ТБ кабинета |
| Активные методы | `lib/active-methods.ts` | 44 приёма по пяти ролям в сценарии урока: настрой, вызов, изучение нового, применение, рефлексия. У каждого — длительность и привязка к характеру темы |
| ИКТ-ресурсы | `lib/ict.ts` | 24 цифровых ресурса (PhET, MolView, Ptable, виртуальные лаборатории, Kahoot!, Quizizz, Wordwall, LearningApps, Plickers, Mentimeter, Padlet, BilimLand, okulyk.kz, Kundelik.kz, документ-камера и другие) с указанием этапа и задачи |
| Связки урока | `lib/lesson-blocks.ts` | Организационный момент, целеполагание, закрепление, обратная связь, базовые ресурсы — по несколько формулировок на каждую позицию |
| Движок | `lib/generator.ts` | Разбор целей обучения, распределение времени по трём этапам, сборка «рецепта» урока из каталогов и заполнение пяти колонок хода урока |
| Claude API | `lib/claude.ts` + `app/api/suggest/route.ts` | Необязательная доработка формулировок под конкретную тему |

### Покрытие программы

Программа 7–9 классов построена на пяти содержательных линиях — «Частицы
вещества», «Закономерности химических реакций», «Энергетика в химии», «Химия
вокруг нас», «Химия и жизнь»; отсюда и кодировка целей обучения вида
`класс.раздел.подраздел.цель`. Программа 10–11 классов естественно-математического
направления (приказ МОН РК № 415 от 20.08.2021) разворачивает те же линии в
самостоятельные разделы.

| Класс | Разделов | Тем |
|---|---|---|
| 7 | 5 | 18 |
| 8 | 5 | 24 |
| 9 | 5 | 24 |
| 10 | 6 | 22 |
| 11 | 6 | 19 |
| **Итого** | **27** | **107** |

В каждом разделе минимум три темы: по разделу учитель ведёт несколько уроков,
и при одной теме все они получали бы один и тот же опыт. Порог проверяется
командой `npm run verify:coverage` на каждом прогоне.

Локальный слой **работает офлайн** — это сознательное решение: связь в школах
нестабильна, а план нужен к началу урока. Claude API подключается ключом и
только дошлифовывает результат; при любой ошибке приложение остаётся на
локальном плане и сообщает об этом.

Тема урока сопоставляется с базой по токенам с учётом морфологии: ключ-основа
ловится префиксом («реакц» → «реакции»), расхождение окончаний с обеих сторон —
общим префиксом от шести букв («карбоновая» ↔ «карбоновые»). Вес ключевого слова
равен его длине, а указанный класс повышает вес тем своей параллели, поэтому
«Карбоновые кислоты» в 11 классе уходит к органике, а не к неорганическим
кислотам 8 класса. Если темы в базе нет, собирается универсальный каркас, и
интерфейс об этом предупреждает.

### Разнообразие планов

Первая версия движка держала начало и конец урока захардкоженными строками, и
по двадцати темам выходило 15 различных формулировок в графе «Действия
обучающихся» на 220 строк — то есть один и тот же урок с подставленной темой.

Теперь сценарий не зашит в код. Генератор сначала собирает «рецепт» — приём
настроя, приём вызова, приём изучения нового, приём применения, приём
рефлексии, цифровые ресурсы на каждый этап, пару «поддержка / усложнение»,
формат домашнего задания, — и только потом раскладывает его по трём этапам.
Рецепт учитывает время: практическая часть занимает ядро середины урока, а
приёмы подбираются из того, что останется. Если на приём применения времени
не хватает, его не будет вовсе — лучше пустая строка, чем план на час в
сорокаминутном уроке.

Приём рефлексии замыкает начало урока: если класс заполнял таблицу ЗХУ, лист
верных и неверных утверждений или кластер, в конце возвращаются именно к ним.

Кнопка **«Другой вариант урока»** пересобирает тот же урок из других приёмов и
ресурсов. Номер сценария сдвигает выбор в каждом пуле, поэтому по одной теме
можно подготовить несколько непохожих уроков — например, на параллель или на
повторный год.

Разнообразие измеряется, а не декларируется: `npm run verify:variety` строит
планы по всей программе и проверяет долю общих строк у двух случайно взятых
планов, число различных формулировок, самую назойливую строку, наличие ИКТ на
каждом этапе каждого плана и расхождение вариантов между собой.

### Привязка приёмов к этапам урока

У темы есть необязательное поле `stagePlan`: один-два приёма или цифровых
ресурса, закреплённых за конкретным этапом. Закрепление адресное — приём
занимает позицию своей роли, цифровой ресурс идёт в графу «Ресурсы», приём
оценивания в графу «Оценивание».

```ts
stagePlan: {
  start: ["true-false", "mentimeter"],
  middle: ["station-rotation", "phet"],
  end: ["google-forms", "exit-ticket"],
},
```

Поле намеренно неполное. Закрепить всё за всеми темами — значит вернуть ровно
то, на что жаловался учитель: одинаковые планы. Поэтому закрепляют только то,
без чего тема методически проседает, а остальные позиции генератор по-прежнему
подбирает из пулов и меняет от варианта к варианту.

`npm run verify:coverage` проверяет каждое закрепление: идентификатор должен
существовать, приём — относиться к тому этапу, за которым закреплён, и
подходить характеру темы. Опечатку генератор молча пропустил бы, и учитель
никогда бы не узнал, что закрепление не сработало.

### Современные подходы: три галочки

Галочки меняют **сам план**, а не только запрос к Claude, — иначе у школы без
ключа API они ничего бы не делали.

| Галочка | Что происходит локально | Что добавляется в промпт |
|---|---|---|
| CLIL | Термины урока в триплете казахский — русский — английский и речевой образец в середине урока; блок «Языковые цели» включается в документе | Требование ввести до пяти терминов в триплете, дать речевой образец на английском и связать тему с элементами STEM |
| Виртуальная лаборатория | В середину урока обязательно попадает симуляция — PhET, ChemCollective или виртуальная лаборатория BilimLand | Требование назвать конкретную симуляцию и описать, что в ней делают, оставив реальный опыт в плане |
| Геймификация | Приёмы с игровой механикой в позициях настроя и применения, сервисы викторин в ресурсах начала и конца урока | Требование дать игровой приём с правилами и критерием победы плюс сервис викторин |

Гарантии проверяются: `npm run verify:variety` строит планы по всей программе и
убеждается, что при включённой галочке симуляция, сервис викторин и триплет
терминов есть в каждом плане. `npm run verify:claude` проверяет, что правило
попадает в промпт **только** при своей галочке: правило, действующее всегда,
модель начинает применять и там, где оно мешает.

### Выгрузка базы знаний в JSON

```bash
npm run export:kb        # data/methods.json, data/topics.json, data/topics-sample.json
```

- `methods.json` — справочник по пяти категориям: ведущие методики, активные
  приёмы, цифровые технологии, формативное оценивание, дифференциация. У
  каждой записи `id`, `name`, `description` и `chemistry_example`; казахский
  вариант лежит в соседнем поле с суффиксом `_kk`.
- `topics.json` — все 107 тем с разделами, опытами, терминами, критериями и
  закреплениями по этапам, где они есть.
- `topics-sample.json` — только темы с `stagePlan`, компактный пример.

Источник правды — каталоги в `lib/`: они типизированы, их проверяют `tsc`,
`eslint` и скрипты `verify`, а генератор читает их напрямую. JSON порождается
из них и не редактируется вручную — две копии одних и тех же данных разошлись
бы через месяц.

### Библиотека планов

Готовый план сохраняется кнопкой «Сохранить в библиотеку»: список лежит в
`localStorage`, данные не покидают устройство учителя. План можно открыть,
дублировать и удалить. Текущая работа автосохраняется черновиком, поэтому
перезагрузка страницы ничего не теряет.

Если браузер блокирует данные сайта (приватное окно, жёсткие настройки),
библиотека и автосохранение отключаются, приложение говорит об этом прямо и
продолжает работать: план по-прежнему можно сразу скачать в DOCX или PDF.

## Структура КСП: два уровня

**Уровень A — строгая форма приказа № 130** (всегда в документе):

- Шапка из восьми полей: раздел долгосрочного плана, ФИО педагога, дата,
  класс, количество присутствующих и отсутствующих, тема урока, цели обучения
  по программе, цели урока.
- Таблица «Ход урока» — ровно пять колонок: этап урока и время, действия
  педагога, действия обучающихся, оценивание, ресурсы.
- Три обязательные строки: начало, середина и конец урока.

**Уровень B — методические блоки** (тумблеры, по умолчанию частично включены):
критерии оценивания, дескрипторы, языковые цели, привитие ценностей,
межпредметные связи, предварительные знания, дифференциация (поддержка и
усложнение), здоровье и соблюдение техники безопасности, рефлексия по уроку.

Выключив все тумблеры, получаете ровно то, что предписано приказом.

## Формулировки формы — один файл

Все надписи полей КСП на русском и казахском живут в **`lib/ksp-template.ts`**.
Интерфейс, экспорт в DOCX и экспорт в PDF читают строки оттуда, поэтому
сверка с официальным текстом приказа — правка одного файла.

> **Требует сверки с официальным PDF.** Состав полей (8 в шапке, 5 колонок × 3
> этапа) подтверждён перекрёстно по нескольким источникам, но падежные варианты
> «Действия ученика» ↔ «Действия обучающихся» и «Оқу мақсаттары» ↔ «Оқыту
> мақсаттары» требуют финальной сверки. Исследование и источники:
> [`docs/01-issledovanie-ksp.md`](docs/01-issledovanie-ksp.md).

## Экспорт

Приказ прямо предписывает хранение КСП в бумажном или электронном формате
Word либо PDF — приложение выгружает ровно эти два.

Казахские буквы (ә ғ қ ң ө ұ ү һ і и заглавные) проверены в обоих форматах:
встроенный в `pdfmake` шрифт Roboto содержит все 18 глифов, что подтверждено
разбором таблицы cmap шрифта и ToUnicode-карты готового PDF.

## Проверка

```bash
npm run verify                     # типы, линтер, покрытие, сопоставление, разнообразие, экспорт, Claude
npm run verify:coverage            # в каждом разделе программы минимум три темы
npm run verify:match               # сопоставление темы с базой, 113 случаев
npm run verify:variety             # планы не повторяют друг друга, ИКТ есть на каждом этапе
npm run verify:claude              # путь доработки через Claude API без ключа
npm run verify:export              # DOCX и PDF совпадают с планом построчно
```

`npm run verify:export` кладёт готовые файлы в указанный каталог
(по умолчанию `/tmp/ksp-verify`) и сверяет их с планом: DOCX распаковывается
и проверяется построчно (все строки на месте, три таблицы, четыре строки в
«Ходе урока»), у PDF читается карта ToUnicode — перечень символов, которые
документ реально умеет показать. Если бы шрифт не покрывал казахскую букву,
в карте её бы не было, а в документе на её месте стоял бы пустой
прямоугольник. Обе проверки испытаны намеренно внесёнными поломками:
выброшенной колонкой «Ресурсы» и иероглифом, которого нет в Roboto.

Чего эта проверка не делает: она не доказывает, что текст не обрезан
рамкой ячейки. Вёрстку по-прежнему нужно смотреть глазами.

`npm run verify:coverage` дополнительно ловит рассинхрон базы: тему со ссылкой
на несуществующий раздел, несовпадение класса темы и раздела, неизвестную
методику, дубль идентификатора, тему без опыта или без критериев.

`npm run verify:variety` считает попарное сходство планов по каждой колонке.
Доля уникальных строк сама по себе обманчива — она упирается в размер пула:
при двадцати приёмах оценивания и четырёх строках на план выше 20 % она не
поднимется даже при идеальном разбросе. Поэтому решающая метрика — то, что
учитель и видит: сколько строк совпадает у двух разных планов.

`npm run verify:claude` подставляет заглушку клиента и прогоняет тот же код,
который выполняется в продакшене: сборку запроса, схему ответа, отказ модели,
сетевую ошибку, отсутствие ключа и слияние результата с планом. Ключ для этого
не нужен; если `ANTHROPIC_API_KEY` задан, скрипт дополнительно делает один
настоящий запрос.

## Развёртывание

Приложение — обычный Next.js, поэтому годится любой хостинг, умеющий его
запускать. Проще всего Vercel:

1. Форкнуть или импортировать репозиторий на [vercel.com](https://vercel.com).
2. Ничего не настраивать: Next.js определяется автоматически.
3. При желании добавить переменную окружения `ANTHROPIC_API_KEY` — она включит
   кнопку «Доработать через Claude». Без неё приложение полностью работоспособно.

Без хостинга, на школьном компьютере:

```bash
npm install
npm run build
npm run start        # http://localhost:3000
```

Библиотека планов хранится в браузере, поэтому серверная база данных не нужна
ни в одном из вариантов.

## Известные ограничения

- Автономный файл хранит библиотеку планов в браузере, а не внутри себя.
  Замена файла новой версией по тому же пути библиотеку сохраняет — проверено
  в Chromium. Но привязка хранилища к `file://` у браузеров разная: в Firefox
  каждый файл может считаться отдельным источником, поэтому файл лучше держать
  на одном месте, а планы, которые жалко потерять, сразу выгружать в DOCX.
- Переключение языка пересобирает план, поэтому ручные правки в ячейках при
  смене языка теряются. Приложение предупреждает об этом до переключения и
  предлагает сохранить план в библиотеку; реквизиты формы сохраняются в любом
  случае.
- Сопоставление темы работает без морфологического анализатора. Расхождения
  окончаний покрываются сравнением по общему префиксу, но короткие слова вроде
  «связи» и «связей» расходятся уже на четвёртой букве — для них в базе
  перечислены обе словоформы. Регрессии ловит `npm run verify:match`.
- База знаний покрывает 107 тем по всем 27 разделам программы, но не каждый
  урок внутри раздела. Для темы вне базы генерируется корректный по структуре,
  но обобщённый каркас — здесь помогает доработка через Claude.
- Разделы 10–11 классов соответствуют естественно-математическому направлению.
  Для общественно-гуманитарного направления курс короче, и часть разделов
  избыточна.
